PROJECT REGISTRY, AI SYSTEM INSTRUCTIONS & RESPONSIVE URLS (v0.1.19)

First-Class Projects, Custom AI System Guidelines & Responsive Architecture

The system introduces first-class Project entities governed strictly by repository identity: gitHost + repositoryPath (e.g. gitlab.company.com/frontend/storefront-pwa). Each project supports tailored AI System Instructions & Guidelines that are dynamically injected into the system prompt of all specialist AI agents during code reviews. All URL displays, input boxes, and meta panels are fully responsive across all viewports with zero horizontal overflow.

Dual Ingestion Modes

Register projects manually from the UI or let the system auto-create and link them when any MR/PR URL is submitted.

Zero-Duplicate Engine

Normalized path hashing ignores .git extensions, trailing slashes, and MR subpaths, guaranteeing clean deduplication.

Custom AI Guidelines

Attach team-specific architectural rules, Persian UI mandates, or lint constraints that are fed to AI models as high-priority system context.

Responsive URLs

Robust word-break and viewport-adaptive containers ensure long repository and MR URLs never break layouts on mobile or desktop.

سامانه مدیریت پروژه‌ها، دستورات سیستمی هوش مصنوعی و طراحی ریسپانسیو (نسخه ۰.۱.۱۹)

مدیریت مستقل پروژه، تزریق دستورالعمل‌های اختصاصی به هوش مصنوعی و نمایش ریسپانسیو آدرس‌ها

در این نسخه، علاوه بر ثبت هویت یکتای پروژه‌ها بر مبنای gitHost + repositoryPath، امکان **تعریف و ویرایش دستورات سیستمی (System Instructions) اختصاصی برای هر پروژه** فراهم شده است. این دستورات به عنوان کانتکست با اولویت بالا مستقیماً به پرامپت ارکستراتور و تمام ایجنت‌های هوش مصنوعی ارسال می‌شوند تا کدها دقیقاً بر اساس الگوهای اختصاصی، معماری و الزامات زبان تیم شما ارزیابی شوند. همچنین نمایش آدرس‌های طولانی URL در تمام صفحات و دستگاه‌های موبایل کاملاً ریسپانسیو و بهینه‌سازی شد.

ثبت خودکار و دستی

امکان تعریف دستی پروژه به همراه توضیحات، و تشخیص و ایجاد خودکار با ارسال لینک‌های GitLab و GitHub.

پیشگیری قطعی از تکرار

نرمال‌سازی کلید یکتا و هدایت تمام درخواست‌های ادغام (MR) مرتبط به یک موجودیت مشخص پروژه.

دستورات سیستمی AI

امکان ثبت دستورالعمل‌های معماری، امنیتی، نام‌گذاری یا الزامات فارسی که مستقیماً به مدل‌های هوش مصنوعی منتقل می‌شوند.

طراحی ریسپانسیو آدرس‌ها

شکست خودکار آدرس‌های طولانی (Word-Break) و عدم سرریز افقی در نمایشگرهای موبایل و تبلت.

ENTERPRISE RBAC, ENCRYPTED GIT CREDENTIALS & AUDIT LOGS (v0.2.0)

Comprehensive User Management, Project Access Control & Zero-Trust Security

The platform features a complete multi-user access control foundation designed for engineering teams. It provides PBKDF2 (SHA-512) password hashing, 256-bit cryptographically secure sessions with revocation, rate-limited login protection, and an automated First-Run Admin Setup Wizard. Security is enforced through system-level RBAC (ADMIN, MEMBER) and project-level roles (OWNER, MANAGER, REVIEWER, VIEWER), complemented by AES-256-GCM encrypted Git credentials and immutable audit trails.

First-Run & Cryptography

Dedicated initial setup creates the first administrator and permanently deactivates; passwords hashed with PBKDF2 and random 16-byte salt.

Multi-Tier RBAC

Backend-enforced system and project roles with permissions checking, project membership management, and last-admin deletion safety.

Encrypted Git Tokens

Per-user GitHub and GitLab PATs encrypted via AES-256-GCM authenticated cipher; masked in UI and never returned in API payloads.

Audit Trail & Rate Limiting

Fixed-window rate limiter with temporary blocks prevents credential stuffing; queryable audit logs record security and membership events with automated redaction.

سیستم جامع مدیریت کاربران، سطوح دسترسی RBAC، رمزنگاری و ثبت رویدادها (نسخه ۰.۲.۰)

احراز هویت سازمانی، مدیریت دسترسی پروژه‌ها و امنیت Zero-Trust با رمزنگاری پیشرفته

پلتفرم مجهز به زیرساخت کامل مدیریت کاربران چندسطحی و دسترسی پروژه‌محور شد. این سیستم شامل هش ایمن گذرواژه با PBKDF2 (SHA-512)، سشن‌های تصادفی رمزنگاری‌شده ۲۵۶ بیتی با قابلیت ابطال، محافظت در برابر حملات Brute-force با Rate Limiting و صفحه راه‌اندازی اولیه اولین ادمین سیستم (First-Run Setup) است. تفکیک نقش‌های سیستمی (ADMIN و MEMBER) و نقش‌های پروژه (OWNER، MANAGER، REVIEWER، VIEWER)، ذخیره‌سازی رمزنگاری‌شده AES-256-GCM برای دسترسی‌های GitHub و GitLab و ثبت تغییرناپذیر لاگ‌های امنیتی (Audit Logs) با حذف خودکار اطلاعات حساس پیاده‌سازی شده است.

راه‌اندازی اولیه و رمزنگاری

صفحه اختصاصی ایجاد اولین مدیر سیستم که پس از تعریف غیرفعال می‌شود؛ هش PBKDF2 با سالت تصادفی و مقایسه زمان‌ثابت.

کنترل دسترسی دولایه (RBAC)

اعتبارسنجی دقیق سمت سرور برای نقش‌های سیستمی و پروژه‌ای، مدیریت اعضای پروژه و محافظت از حذف آخرین ادمین سیستم.

توکن‌های رمزنگاری‌شده گیت

ذخیره‌سازی امن PATهای گیت‌هاب و گیت‌لب هر کاربر با رمزنگاری AES-256-GCM، نمایش ماسک‌شده و تضمین عدم نشت در API.

لاگ‌های امنیتی و Rate Limit

محدودکننده نرخ ورود برای جلوگیری از حملات Brute-force، و ثبت تغییرناپذیر رویدادهای احراز هویت و دسترسی با حذف داده‌های محرمانه.

DETERMINISTIC BENCHMARK HARNESS & KUHN-MUNKRES MATCHING (v0.2.2)

Benchmark Dataset & Deterministic Evaluation Harness

The @ai-review/eval subsystem introduces an empirical evaluation harness designed to objectively measure code review quality against verified ground truth. Hardened in v0.2.2 with zero-cost Quadrant III unmatched expected slots, $O((m+n)^3)$ equality-subgraph Reverse-BFS lexicographic tie-breaking, strict (>) dual-match quarantine, and complete UAR and filteredRecallLoss accounting.

Kuhn-Munkres Matcher

Maximum-weight partial matching with safe forbidden edge penalties and canonical two-stage lexicographic tie-breaking.

Dual-Match Quarantine

Candidates triggering both expected findings and anti-findings are quarantined into Q to prevent silent metric inflation.

Dataset Provenance

Full lineage tracking for benchmark cases: origin tagging (synthetic, MRs, human feed) and peer-review verification states.

Unbiased Quality Metrics

Conservative and confirmed bounds, Hopcroft-Karp UQ matching, AFTR trap capture rate, and False Discovery Penalty Cost.

مجموعه داده‌های استاندارد، تطبیق دوبخشی مجارستانی و سنجه‌های ارزیابی بدون سوگیری

تطبیق بیشینه‌وزن مجارستانی

شناسنامه و اصالت داده‌ها

رهگیری شجره‌نامه موارد آزمون (تست ساختگی، MR تاریخی، فید بازبینی انسانی) و مدیریت نسخه‌های برچسب‌گذاری.

شاخص‌های محافظه‌کارانه و تجاری

PROJECT INTELLIGENCE 2A • STRUCTURAL REPOSITORY INDEX (v0.2.3)

Multi-Source Structural Repository Indexing & Dependency Graph Engine

The @ai-review/project-index package enables deep structural comprehension of registered repositories across GitLab REST v4, GitHub Trees/Blobs APIs, and local checkouts. It enforces .gitignore and size filters, extracts TypeScript/JS AST symbols and imports via @ai-review/context-engine, resolves monorepo workspaces and tsconfig path aliases into a bidirectional dependency graph, and persists snapshots atomically with incremental gitBlobSha and contentHash reuse.

هوشمندی پروژه (فاز 2A) • ایندکس ساختاری مخازن و گراف وابستگی (نسخه ۰.۲.۳)

ایندکس ساختاری چندمنبعی، گراف وابستگی ماژول‌ها و ذخیره‌سازی افزایشی اسنپ‌شات‌ها

پکیج جدید @ai-review/project-index امکان واکشی و تحلیل ساختاری مخازن را از GitLab، GitHub و پوشه‌های محلی (Local) فراهم می‌سازد. این موتور با اعمال قوانین .gitignore، استخراج AST برای فایل‌های TypeScript/JS، تشخیص پکیج‌های Monorepo و tsconfig paths، بازاستفاده افزایشی بدون دانلود مجدد فایل‌های تغییرنیافته (gitBlobSha) و مدیریت Job با قابلیت لغو و رعایت Retry-After، زیربنای هوشمندی پروژه را فراهم می‌کند.

SECURITY • API HARDENING (v0.2.4)

Authenticated APIs & Safe Local Apply

Every project, review, estimate, publish, model-listing and apply-local endpoint now requires a signed-in user. apply-local only edits files inside the given repository root, rejecting path traversal and symlinks that escape it. Runtime data in .data/ is no longer tracked by git.

امنیت • سخت‌سازی API (نسخه ۰.۲.۴)

ایندکس پروژه‌ها از داخل رابط کاربری

تب جدید Index در هر پروژه، یک Job ایندکس قابل لغو برای مخازن GitHub یا GitLab اجرا می‌کند و پیشرفت زنده، تعداد فایل‌ها و سمبل‌ها، توزیع زبان‌ها، پکیج‌های workspace و پر‌ایمپورت‌ترین فایل‌ها را نشان می‌دهد. ایندکس با توکن رمزنگاری‌شده Git خود کاربر انجام می‌شود؛ شروع آن نیازمند دسترسی project:manage و مشاهده‌اش نیازمند project:view است.

PROJECT INTELLIGENCE • INDEX-AWARE REVIEWS (v0.2.8)

Reviewers That See Beyond the Diff

For every changed file, reviewers now receive its exports, its imports and the files that depend on it, with dependants outside the change called out as potential breakage. Indexing starts automatically in the background for new or stale projects. Model prices come from your providers, so budgets and cost metrics are real.

هوشمندی پروژه • ریویو آگاه از ایندکس (نسخه ۰.۲.۸)

ریویوکننده‌هایی که فراتر از دیف را می‌بینند

برای هر فایل تغییرکرده، ایجنت‌ها exportها، importها و فایل‌های وابسته را دریافت می‌کنند و وابسته‌های خارج از تغییر به‌عنوان ریسک شکستن مشخص می‌شوند. ایندکس برای پروژه‌های جدید یا قدیمی به‌صورت خودکار در پس‌زمینه اجرا می‌شود. قیمت مدل‌ها از پروایدرهای شما خوانده می‌شود تا بودجه و هزینه‌ها واقعی باشند.

RELEASE NOTES

What's New

  • v0.4.0 — AI Providers: the model field is now a searchable picker (Fetch List) showing context size and, when the provider reports it (OpenRouter, Together), per-model price; picking a model fills Input / Output cost automatically.
  • v0.3.2 — Security: the server's own AI and Git keys are never sent to an endpoint or host chosen in the request, and requests can only lower budgets. Reviews are more robust: one failing specialist no longer drops the report (its error is listed), retries back off, duplicate findings merge across category names, Go/Rust/PHP/Ruby/C++ changes get the general reviewers, the security reviewer uses the premium model, the chosen comment language is applied, and the AI response cache is per model (AI_REVIEW_LLM_CACHE=0 to disable).
  • v0.3.1 — New no-AI rule security.prompt-injection flags lines that try to instruct AI reviewers (critical); prompt-cache warm-up runs one specialist first so the others reuse the provider cache (AI_REVIEW_CACHE_WARMUP=0 to disable).
  • v0.3.0 — Hardened AI review prompts: MR content (including changed AGENTS.md / CONTRIBUTING.md) can no longer steer reviewers and injection attempts are reported as critical; line-numbered diffs with findings anchored to changed lines; shared prompt prefix for provider prompt caching; strict JSON schema output with automatic fallback.
  • v0.2.43 — Review & Publish summary panel: MR title/link/author/branches, per-severity counts (selected/total), files, categories, average confidence and Select all / none. The redundant "Pre-Review Findings" box was removed.
  • v0.2.42 — Review & Publish: Select all / Select none buttons with a live "N of M selected" counter.
  • v0.2.41 — New Add to comment button next to Commit to branch on AI sample fixes: appends the code to the PR comment as a Git suggestion block (with an Apply button on the Git host).
  • v0.2.40 — Fix: the "release change required" rule now accepts any changelog / release-notes file name (e.g. CHANGELOG.fa.md), removing a false finding.
  • v0.2.39 — Lower AI cost: project guidelines are split by ## headings so each specialist gets only its sections; new "Fix, improve & shorten with AI" button and a token counter in the guidelines editor.
  • v0.2.38 — Removed the redundant Identity & Deduplication tab from the project page.
  • v0.2.37 — Developers tab shows the reviewer's grade note and the suggestion reason under each MR.
  • v0.2.36 — Fix: reviews from the Review page are always linked to their MR, so the suggested grade and author show right after the review.
  • v0.2.35 — Next.js Reviewer is no longer suggested for plain React projects; it needs real Next.js signals.
  • v0.2.34 — Re-Estimate no longer re-ticks specialists you unticked (e.g. Next.js reviewer); your selection is kept.
  • v0.2.33 — MR task grades now use a 0-10 scale (suggested grade and developer averages too); old grades convert automatically.
  • v0.2.32 — Clearer "Estimate AI usage" button; grade card and button also show on Review results restored from an earlier session.
  • v0.2.31 — Estimate / Re-estimate button for reviewers: estimated % chance an MR was written with AI (rules + AI judge), with reasons; separate from the review.
  • v0.2.30 — MR author is fetched as soon as you enter the MR URL (using your Git token), not only after a review.
  • v0.2.29 — Review page shows a grade card for the reviewed MR: author, suggested grade with reason, and a form for reviewers to set the grade.
  • v0.2.28 — Developers tab in each project: MR authors with MR count, average grade and average suggested grade, expandable to their MRs.
  • v0.2.27 — MR task grades: each MR shows its author from Git and a 0-100 task-completion grade set by reviewers, with a system-suggested grade and short reason, plus a per-developer average.
  • v0.2.26 — The server now runs on port 4000 by default (Docker image too); PORT and --port still override it.
  • v0.2.25 — Project Scan tab: choose a branch and scan the whole repository with the built-in rules (no AI), with a filterable report and history.
  • v0.2.24 — Rules-only (no AI) review with multi-language rules (Python, Java, C#, PHP, Go, Kotlin, Swift, shell, Docker); Rule checks (no AI) only flag lines changed in the diff, repeated findings of one rule in a file are no longer merged, and optional branch-name / MR-title checks (AI_REVIEW_GOVERNANCE_RULES=1).
  • v0.2.23 — Feedback on each finding (useful / not useful) with an optional "Add to project rules" checkbox that updates the project's instructions.
  • v0.2.22 — Review MR from a project now opens that MR's saved review instead of a stale or empty result.
  • v0.2.21 — "Open in Git" link on each Review & Publish card.
  • v0.2.20 — Warning when no AI provider is connected or specialists fail; code preview shows why it is missing and falls back to the review diff.
  • v0.2.19 — Redesigned Review & Publish cards (code, full comment info, RTL) and an AI sample-fix button with copy and commit.
  • v0.2.18 — Release notes system: bilingual CHANGELOG, this section and an automated version check.
  • v0.2.17 — Security: Git tokens are never sent to the wrong host; connection test blocks loopback/metadata addresses.
  • v0.2.16 — Per-project index history (last 50 jobs).
  • v0.2.15 — Index refreshes when the target branch moves; review context overlays the diff on the index.
  • v0.2.14 — Per-branch index; reviews use the MR/PR target branch.
  • v0.2.13 — Deep links for tabs and projects; Index tab uses the matching Git connection.
  • v0.2.12 — Multiple Git connections with a Test Connection button.

یادداشت‌های انتشار

تازه‌ها

  • نسخه ۰.۴.۰ — AI Providers: فیلد مدل حالا یک انتخابگر جستجوپذیر است (Fetch List) که اندازه context و، اگر provider قیمت را اعلام کند (OpenRouter، Together)، قیمت هر مدل را نشان می‌دهد؛ با انتخاب مدل، Input / Output cost خودکار پر می‌شود.
  • نسخه ۰.۳.۲ — امنیت: کلیدهای AI و Git خود سرور هرگز به endpoint یا هاستی که در درخواست انتخاب شده ارسال نمی‌شوند و درخواست فقط می‌تواند بودجه را کمتر کند. ریویو پایدارتر شد: خطای یک specialist دیگر گزارش را از بین نمی‌برد (خطایش نمایش داده می‌شود)، تلاش مجدد با فاصله افزایشی است، یافته‌های تکراری با نام دسته متفاوت ادغام می‌شوند، تغییرات Go/Rust/PHP/Ruby/C++ ریویوکننده‌های عمومی را می‌گیرند، ریویوکننده امنیت از مدل premium استفاده می‌کند، زبان انتخابی کامنت‌ها اعمال می‌شود و کش پاسخ AI برای هر مدل جداست (با AI_REVIEW_LLM_CACHE=0 خاموش می‌شود).
  • نسخه ۰.۳.۱ — قانون جدید بدون AI به نام security.prompt-injection خطوطی را که بخواهند به ریویوکننده AI دستور بدهند علامت می‌زند (critical)؛ گرم‌کردن کش پرامپت: یک specialist اول اجرا می‌شود تا بقیه از کش سرویس‌دهنده استفاده کنند (با AI_REVIEW_CACHE_WARMUP=0 خاموش می‌شود).
  • نسخه ۰.۳.۰ — سخت‌سازی پرامپت ریویو AI: محتوای MR (از جمله AGENTS.md / CONTRIBUTING.md تغییرکرده) دیگر نمی‌تواند ریویوکننده‌ها را هدایت کند و تلاش برای prompt injection به‌عنوان یافته critical گزارش می‌شود؛ diff با شماره خط و انتقال یافته‌ها به خطوط تغییرکرده؛ ابتدای پرامپت مشترک برای کش پرامپت سرویس‌دهنده؛ خروجی با schema دقیق JSON و بازگشت خودکار.
  • نسخه ۰.۲.۴۳ — پنل خلاصه Review & Publish: عنوان/لینک/نویسنده/شاخه‌های MR، تعداد هر شدت (انتخاب‌شده/کل)، فایل‌ها، دسته‌ها، میانگین اطمینان و Select all / none. باکس تکراری «Pre-Review Findings» حذف شد.
  • نسخه ۰.۲.۴۲ — Review & Publish: دکمه‌های Select all و Select none با شمارنده «N از M انتخاب شده».
  • نسخه ۰.۲.۴۱ — دکمه جدید Add to comment کنار Commit to branch در نمونه‌کد AI: کد را به‌صورت بلاک suggestion گیت به کامنت PR اضافه می‌کند (با دکمه Apply در Git).
  • نسخه ۰.۲.۴۰ — رفع خطا: قانون «ثبت release الزامی است» اکنون هر نام فایل changelog / release-notes (مثل CHANGELOG.fa.md) را می‌پذیرد و یافته اشتباه حذف شد.
  • نسخه ۰.۲.۳۹ — کاهش هزینه AI: دستورالعمل‌های پروژه با سرتیتر ## تقسیم می‌شوند و هر specialist فقط بخش مربوط به خودش را می‌گیرد؛ دکمه جدید «Fix, improve & shorten with AI» و شمارنده توکن در ویرایشگر.

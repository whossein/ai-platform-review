# کارهای باقی‌مانده: Skills & Rules و موتور ریویو

فهرست کارهایی که بعد از نسخهٔ 0.8.0 مانده‌اند. هر مورد طوری نوشته شده که بدون تاریخچهٔ گفتگو هم قابل اجرا باشد.

برای شروع کار کافی است بگویید مثلاً: «مورد ۱۲ از `docs/REVIEW-BACKLOG.md` را انجام بده».

**قبل از شروع:** شماره خط‌ها مربوط به زمان نوشتن هر مورد هستند و ممکن است جابه‌جا شده باشند؛ کد فعلی را دوباره چک کنید. قوانین نسخه، Changelog و مستندات دوزبانه در `AGENTS.md` هم برای این کارها لازم است. بعد از انجام هر مورد، آن را از این فایل حذف کنید.

## اولویت بالا

### ۱۲. یافته‌های تکراری بین دسته‌های مختلف
**وضعیت:** در 0.7.0 یافته‌های یک خط با دسته‌های متفاوت فقط با شواهد ادغام می‌شوند (عنوان یکسان یا شباهت متنی حداقل ۰٫۵). در 0.8.0 معیار سومی اضافه شد: دو یافتهٔ هم‌مکان با عنوان‌های بسیار شبیه (حداقل دو کلمهٔ مشترک و نصف اتحاد کلمات) ادغام می‌شوند. این معیار با تست واحد پوشش داده شده و در دو اجرای زندهٔ 0.8.0 recall برابر ۱۰۰٪ ماند، اما اثرش روی نمونهٔ `v2-04` (نشت `BufferedReader`) دیده نشد: مدل‌ها در اجرای دوم هم آن را با عنوان‌هایی مثل «Reader is never closed, leaking file descriptors» و «File descriptor leak...» نوشتند که با هم کلمهٔ کافی ندارند، و هنوز سه یافته تحویل شد. در اجرای اول هم یکی از یافته‌ها به‌جای خط ۹ روی خط ۱۰ آمد و چون مکانش فرق دارد اصلاً هم‌گروه نمی‌شود.

**کار:** هنوز راه مطمئنی که این گزارش‌ها را ادغام کند و recall را کم نکند پیدا نشده. گزینهٔ باقی‌مانده یک مرحلهٔ ادغام با LLM است (یک تماس ارزان روی یافته‌های هم‌فایل با فاصلهٔ حداکثر ۲ خط که فقط خوشه‌بندی می‌کند و چیزی حذف نمی‌کند). پایین‌آوردن آستانهٔ شباهت به‌تنهایی پرریسک است. نتیجه را با `eval:live` بسنجید و Recall نباید کم شود. Agentها دسته را آزادانه می‌نویسند و مقدار نهایی در UI و Rule خاموش‌کردن هم استفاده می‌شود، پس تغییر آن باید با احتیاط باشد.

## اولویت متوسط






### ۱۴. گسترش دیتاست eval با MR واقعی
**وضعیت:** `packages/eval/datasets/synthetic/v2/` فقط ۱۱ نمونهٔ ساختگی دارد. بعضی FPها مشکل واقعی‌ای هستند که در دیتاست ثبت نشده است (مثلاً `AttributeError` برای کاربر بدون سفارش در نمونهٔ `v2-03`)، پس Precision گزارش‌شده پایین‌تر از مقدار واقعی است.

**کار:** چند MR واقعی اضافه کنید و یافته‌های درستِ اضافه را در `expectedFindings` ثبت کنید. اجرا روی کلیدهای دارای محدودیت: `npm run eval:live -- --pace-ms 15000 --output eval.json`، و برای تطبیق کلیدواژه‌ها `AI_REVIEW_COMMENT_LANGUAGE=en`.
